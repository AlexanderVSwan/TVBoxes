# DNS и DNS-over-HTTPS на X98K

## Назначение

На X98K используется локальная DNS-служба, которая принимает запросы от клиентов Wi-Fi и передаёт их локальному DNS-прокси. Прокси отправляет запросы к внешним DNS-серверам по протоколу DNS-over-HTTPS (DoH).

Такая схема позволяет централизовать обработку DNS-запросов клиентов точки доступа и использовать шифрованное соединение с внешним DNS-провайдером.

## Схема работы

```text
Клиент Wi-Fi
     |
     | DNS-запрос
     v
192.168.8.1:53
   dnsmasq
     |
     | Перенаправление DNS-запроса
     v
127.0.0.1:5053
 dnscrypt-proxy
     |
     | DNS-over-HTTPS
     v
Внешний DNS-сервер
```

Компоненты выполняют разные задачи:

- **dnsmasq** — принимает DNS-запросы от устройств локальной сети, а также раздаёт IP-адреса по DHCP.
- **dnscrypt-proxy** — локальный DNS-прокси, обеспечивающий отправку запросов к внешним серверам через DoH.
- **DoH-сервер** — внешний DNS-провайдер, которому отправляются запросы.

## Сетевая конфигурация

### Локальный DNS

Для клиентов Wi-Fi используется адрес:

| Параметр | Значение |
|---|---|
| DNS-сервер | `192.168.8.1` |
| Порт | `53` |
| Интерфейс | `wlan0` |
| Служба | `dnsmasq` |

Клиенты получают адрес DNS-сервера `192.168.8.1` через DHCP.

### dnsmasq

Конфигурация находится в файле:

`/etc/dnsmasq.d/wlan0.conf`

```ini
# Wi-Fi access point only
interface=wlan0
listen-address=192.168.8.1
bind-interfaces
except-interface=end0

# DHCP
dhcp-authoritative
dhcp-range=192.168.8.100,192.168.8.200,255.255.255.0,12h
dhcp-option=option:router,192.168.8.1
dhcp-option=option:dns-server,192.168.8.1

# DNS via local DoH proxy
no-resolv
server=127.0.0.1#5053

domain-needed
bogus-priv
```

Важные параметры:

- `interface=wlan0` — обслуживание Wi-Fi-интерфейса.
- `listen-address=192.168.8.1` — локальный адрес DNS-службы.
- `no-resolv` — не использовать DNS-серверы из системного `/etc/resolv.conf`.
- `server=127.0.0.1#5053` — передавать DNS-запросы локальному прокси.

Таким образом, dnsmasq не обращается напрямую к внешним DNS-серверам.

## dnscrypt-proxy

Используется `dnscrypt-proxy` версии 2.1.14.

Локальный адрес прослушивания:

```text
127.0.0.1:5053
```

Служба принимает запросы от dnsmasq и отправляет их выбранным внешним DNS-серверам с использованием DNS-over-HTTPS.

Конфигурация dnscrypt-proxy хранится отдельно от настроек точки доступа. Выбор провайдеров, параметры DoH и остальные настройки прокси следует описывать в конфигурации самой службы.

## Проверка работы

### 1. Проверить dnsmasq

```bash
systemctl status dnsmasq
```

Проверить, что DNS-порт прослушивается:

```bash
ss -lnup | grep ':53'
```

### 2. Проверить dnscrypt-proxy

```bash
systemctl status dnscrypt-proxy
```

Проверить локальный порт:

```bash
ss -lnup | grep ':5053'
```

### 3. Проверить DNS-запрос через локальный прокси

```bash
dig @127.0.0.1 -p 5053 example.com
```

### 4. Проверить DNS через dnsmasq

```bash
dig @192.168.8.1 example.com
```

В ответе должны присутствовать DNS-записи и статус `NOERROR`.

### 5. Проверить DNS с клиента Wi-Fi

На подключённом устройстве проверить, что DNS-сервером назначен адрес:

```text
192.168.8.1
```

Затем выполнить обычный DNS-запрос.

## Важные особенности

- DoH шифрует DNS-запросы между dnscrypt-proxy и внешним DNS-провайдером. 
- Локальный dnsmasq использует dnscrypt-proxy как upstream DNS-сервер.
- Если dnscrypt-proxy остановлен, DNS-разрешение через эту цепочку перестанет работать.
- Текущая конфигурация раздаёт клиентам адрес `192.168.8.1` в качестве DNS-сервера, но не запрещает устройствам обращаться к другим DNS-серверам напрямую.
- Использование DoH не гарантирует анонимность: внешний DNS-провайдер по-прежнему получает DNS-запросы.
